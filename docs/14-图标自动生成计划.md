# 14 — 零件 / 装配体图标自动生成计划

> 状态：**草案 v0.4（已吸收 2026-10-22 两轮外部审阅；待实施）** · 日期：2026-10-22 · 范围：Blockbench 插件（不含主模组 MachineMax）
> 目标版本：`0.5.0` · 参照：[03-交互设计](./03-交互设计.md)、[05-开发计划](./05-开发计划.md)、[13-业务逻辑层与配置文档API](./13-业务逻辑层与配置文档API.md)
> 目的：在 Blockbench 内根据当前工程、骨骼显隐和位姿，一键生成符合 MachineMax 现有风格的零件图标与装配体图标。

---

## 1. 背景与目标

### 1.1 现状

| 项 | 现状 |
|---|---|
| 图标字段 | `part.icon` 只是一个字符串，手工填写；见 [part_codec.js](../src/codec/codecs/part_codec.js#L39)、[part_definition_panel.html](../src/ui/panels/part_definition_panel.html#L51) |
| 图标生成 | **没有**。作者需要自己截图、裁剪、缩放到 128×128、放进 `textures/icon/`、再手填路径 |
| 图标复制 | **没有**。导出时只创建空的 `textures/icon/`，不复制任何图标/模型/贴图；见 [export_pipeline.js](../src/services/export_pipeline.js#L175) |
| 装配体图标 | 图片可以手工放，但插件不管理 `assemblies/` / `blueprints/`，导出只建空目录 |
| 变体图标 | Java 侧 `VariantAttr.CODEC` 没有 `icon` 字段，变体级 icon 实际不生效；只有零件级 `part.icon` |

### 1.2 目标

1. 在 Blockbench 内一键生成零件图标，默认 **128×128 PNG、RGBA 透明底**，风格与现有内容包一致。
2. 支持按零件定义自动显隐骨骼，也支持“使用当前手动显隐”。
3. 支持当前姿态（Animate 模式摆好的炮塔/车门等）；不做 rest pose 重置。
4. 支持批量：全部零件 + 整机装配体。
5. 写入前可预览；写入时优先复用现有 `part.icon` 路径，避免破坏已有 `recipe` / `assemblies` / `blueprints` 引用。
6. 批量修改 `part.icon` 只产生**一条撤销记录**；PNG 写盘作为外部副作用，不进撤销栈。
7. 不依赖 MCP 桥；**P1 不新增 MCP 工具**。若未来需要，须按 `docs/12` 显式登记为例外，不能把 `services/` 的写盘/渲染能力直接注册为工具。

### 1.3 非目标

- 不生成/修改模型、贴图、动画、碰撞箱数据。
- 不自动创建模板（`templates/`）或装配体数据；P1 只生成装配体 PNG。
- 不做“重置为 rest pose”；首期只捕当前姿态。
- 不做逐变体图标（mod 数据模型不支持）。
- 不改主模组 Java 代码。

## 2. 调研结论：MachineMax 现有图标格式

### 2.1 官方包与当前包实测

| 项目 | 结论 |
|---|---|
| 官方包图标数量 | 78 张 PNG |
| 尺寸分布 | **62 张 128×128**；16 张为 275×265～938×847 的大图旧资源 |
| 128×128 格式 | PNG **RGBA**，透明背景 |
| 大图旧资源 | alpha 包围盒覆盖整张图，实看为白底/不透明旧图；不建议作为新图标模板 |
| 取景 | 固定相机、统一比例；2S38 内容约占画面 **86%**（约 110px），k17 / sdkfz234 约 **95%**（121–122px）；无阴影、无地面、无网格 |
| 显示模型 | `item_icon_2d_128x` 声明 `texture_width/height = 128`，UV 0–128，贴在一个 16³ 方块的北面 |
| 字段 | **`part.icon` 是零件级**；`VariantAttr` 没有 icon 字段 |
| 路径 | `namespace:textures/icon/...` |
| 命名 | 官方包多用 `{partId}_icon.png`；当前 `sdkfz` 包用 `{partId}.png`，无统一强制后缀 |
| 装配体/蓝图 | `assemblies/*.json`、`blueprints/*.json` 的 `icon`，同样使用 128×128 规格 |

**当前 `sdkfz` 内容包的 15 张图标全部是 128×128 透明 PNG**（其中 2S38 占 7 张），bbox 示例：

| 文件 | bbox（128 画布内） |
|---|---|
| `2s38.png`（整机） | 110×80 |
| `2s38_hull.png` | 110×92 |
| `2s38_turret.png` | 104×110 |
| `2s38_skirt_1.png` | 110×111 |

2S38 这批的最大边都在 110px 左右，说明是“**整机定一次 zoom，每个零件只改中心**”，而不是每件自动填满画面。参考脚本默认 `fill=0.86`，与 2S38 吻合；k17 / sdkfz234 则接近 0.95，因此 fill 不能写死，P1 做成可配置（默认 0.9）。

### 2.2 结论

新图标的目标规格应固定为：

```
PNG / RGBA / 128×128 / 透明底
正交或近等轴测 / 可复现的相机方向（默认项目相机或等轴测） / 统一比例
fill 按项目标定（2S38 约 0.86，k17 / sdkfz234 约 0.95；P1 可配置，默认 0.9）
无阴影、无地面、无网格、无 Locator、无碰撞箱
```

## 3. 可行性证据

### 3.1 当前 2S38 工程的数据足够

对当前打开的 `2S38_Vehicles.bbmodel` 做只读检查：

- Bedrock 格式，153 个 Group、3050 个 Cube。
- 6 个零件：`2s38_hull`、`2s38_turret`、`2s38_skirt_1..4`。
- 所有 `variants[*].sub_parts[*].start_bone` 都能在 `Group.all` 中找到，**没有缺失**。
- `2s38_hull` 有 17 个子零件根（HullRoot + 16 个轮子）；`2s38_turret` 有 2 个（Gun_turret + 2A90）；每块裙板 1 个。
- `2s38_turret` 的 `sub_part.main` 有 `end_bones: ["2A90"]`，但 `2A90` 同时是另一个 sub_part 的起点；按“各 sub_part 的 start 子树减去 end 自身及子树（end ∪ auto_end）后取并集”计算，整炮塔仍然完整。

这意味着“零件 → 可见骨骼组”的映射可以直接从配置推导，不需要人工维护组名清单。

### 3.2 参考脚本已经跑通渲染链路

`%TEMP%\mm_icons.ps1`（另一 agent 编写的临时验证脚本，仅作调研参考，不作为实现依赖）的核心步骤：

1. `Set-OnlyGroups`：保留指定组 + 整棵子树 + 祖先，其余隐藏。
2. `Hide-HitBoxes`：按名字隐藏 hitbox。
3. `Get-VisibleBounds`：用 `Cube.getGlobalVertexPositions()` 量当前姿态下的世界 AABB。
4. `Get-CameraBasis` + `Render-Icon`：正交相机、迭代取景、512 校准、128 输出。

**产物对照**：`final-icons-1.png` 与包内 `2s38_skirt_4.png` 的 SHA-256 完全一致（`2EBC0D77...F4C`），说明这条链路已经实际落到当前内容包里。

参考脚本走 MCP 桥的 `set_camera_angle` / `capture_screenshot`；插件内不需要 MCP，用 Blockbench 原生 API 即可复刻。

### 3.3 Blockbench 原生 API 足够

| 能力 | API | 结论 |
|---|---|---|
| 离屏渲染 | `new Preview({ offscreen: true, antialias: true })` + `preview.resize(w,h)` + `preview.render()` | ✅ |
| 透明背景 | `WebGLRenderer({ alpha: true })` + `setClearColor(0,0)` | ✅ |
| 隐藏辅助元素 | `Canvas.withoutGizmos(cb)` | ✅ |
| 骨骼显隐 | `Group.visibility` / `Group.mesh.visible` / `Cube.all` | ✅ |
| 量当前姿态 AABB | `Cube.getGlobalVertexPositions()`（走 `mesh.matrixWorld`） | ✅ |
| 截图/编码 | `preview.canvas.toDataURL('image/png')` | ✅ |
| 写盘 | Node `fs`（插件已使用） | ✅ |

注意：

- `Screencam.cleanCanvas` 已 **deprecated**，且走主视口；批量/固定取景建议自建 offscreen `Preview`。
- `Screencam.screenshotPreview` 会按内容自动裁剪，不适合“统一比例”的批量图标。
- 不能用 `Canvas.getModelSize()`：它不区分显隐，也不排除 hitbox。

## 4. 方案对比与推荐

### 4.1 三种入口

| 方案 | 描述 | 优点 | 缺点 | 建议 |
|---|---|---|---|---|
| **A. 同级菜单“生成图标…”** | 与“导出内容包”并列，打开独立对话框 | 可预览、可批量、可复用；不污染导出流程 | 多一个入口 | **P1 主方案** |
| **B. 导出对话框勾选“导出前生成图标”** | 导出时顺带生成 | 一键完成 | 导出是同步的；失败/覆盖策略复杂；换导出目录会缺图 | **P2** |
| **C. 属性面板图标行旁小相机按钮** | 只生成当前零件 | 最贴近日常微调 | 批量能力弱 | P1 可选附带 |

**推荐**：P1 做 A（+ 可选 C），P2 做 B。导出入口只作为“确保图标最新”的快捷方式，不承担主要配置。

### 4.2 装配体图标的范围

| 方案 | 内容 | 建议 |
|---|---|---|
| 只生成 PNG | 输出 `2s38/2s38.png`；若已有 `assemblies/{name}.json` 且其 `icon` 指向该路径，生成后**立即生效**；不修改 JSON | **P1 推荐** |
| 同时写 `assemblies/*.json` | 读取/创建 assembly 数据并更新 `icon` | P2/P3；插件目前没有 assembly 数据模型 |
| 不生成装配体 | 只做零件图标 | 不满足需求 |

当前 `sdkfz` 包中 `k17.json`、`sdkfz234_2.json` 的 `icon` 已经指向 `textures/icon/k17/k17.png`、`textures/icon/sdkfz234/sdkfz234_2.png` 这类默认路径，所以生成同名文件即可生效，**不需要手工改 JSON**。2S38 则只有 `2s38.png`、没有 `assemblies/2s38.json`，此时 PNG 只是给后续手工接线用。

## 5. 交互设计

### 5.1 菜单项

在 [menu.js](../src/ui/menu.js#L28) 的“导出内容包”后插入：

```js
{
    name: '生成图标…',
    icon: 'fa-camera',
    id: 'mm_menu_generate_icons',
    click: function () { /* 打开 icon_generator_dialog */ }
}
```

保留分隔线，原有导入/内容包/查看定义项不动。

### 5.2 对话框字段

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 范围 | select | 全部零件 + 装配体 | 当前零件 / 全部零件 / 仅装配体 / 全部 + 装配体 |
| 变体 | select | 自动 | 仅“当前零件”可选；全部零件时按 §6.2 逐零件解析（active 存在则用，否则第一个） |
| 显隐方式 | select | 按零件定义自动显隐 | 自动 / 使用当前显隐（手动摆） |
| 相机方向 | select | 项目相机（首次等轴测） | 项目相机 / 等轴测 / 使用当前视角。**“使用当前视角”只允许 `scope:'current'`**，完整复制当前相机变换；整批/装配体时禁用 |
| 取景 | select | 统一比例 | 统一比例（整机定一次 zoom，零件只移 target）/ 每件填满（每件重算 zoom）。**不再提供“完全当前视角”**；当前视角由相机方向表达 |
| 填充率 | number | 0.9 | 0.5–1.0；2S38 用 0.86，k17/sdkfz234 用 0.95 |
| 图标子目录 | text | 自动 | 仅新建路径使用；已有 `part.icon` 原样保留；输入按 resource path 段校验，非法则拒绝 |
| 分辨率 | info | 128×128 | P1 固定 128；256/512 后续再评估（字段只读） |
| 背景 | select | 透明 | 透明 / 纯色（P3 可选） |
| 姿态 | info | 当前姿态 | 提示先在 Animate 模式或直接旋转骨骼摆好 |
| 隐藏碰撞箱/交互区/连接点 | checkbox | 勾选 | 用 `element_markers` 判定，名称正则兜底 |
| 覆盖已有文件 | checkbox | 关闭 | 关闭时不重写已存在文件；字段为空时仍可只关联已有文件（不写盘），见 §5.4 |
| 改写外部/依赖图标引用 | checkbox | 关闭 | `part.icon` 指向其他 namespace 或非 `textures/icon/` 时，是否把字段改到本包新图标 |

### 5.2.1 对话框形态（定死）

用**两步 Dialog**，避免三按钮和 HTML 字符串：

1. **设置 Dialog**：`form` 放上表字段；主按钮“预览”（`onConfirm`）。确认时先跑 `icon_generator.generate({ write:false })`，不写盘；预览失败时 `return false` 保持设置 Dialog。
2. **预览 Dialog**：`lines: [previewGridElement]`，`previewGridElement` 必须是 **HTMLElement**（不要传 HTML 字符串）；主按钮“写入”，取消“取消”。确认时才写 PNG + 更新 `part.icon`。

预览 Dialog 顶部显示汇总：`新建/关联 N / 覆盖 M / 跳过 K / 未改写 E / 失败 F`，并列出实际使用的变体。用户若要改选项，取消预览、回到设置 Dialog 重来。

汇总按**条目**去重计数，同一个条目只进一类：字段原为空 → 新建（`created`）或只关联已有文件（`linked`）；外部字段勾选改写且目标文件已存在 → `linked`；字段已有且文件被重写 → 覆盖；文件被跳过且字段不变 → 跳过；文件生成但外部字段未改写 → 未改写。

### 5.3 流程

```
点击“生成图标…”
  → 校验 config / contentPackPath / 当前工程
  → 设置 Dialog（范围/变体/显隐/相机/取景/填充率/子目录/覆盖）
  → 确认 = 生成预览（data URL 缩略图，不写盘）
  → 预览 Dialog（新建/关联 N / 覆盖 M / 跳过 K）
  → 确认 = 写 PNG + 批量更新 part.icon + toast 汇总
```

预览不写盘、不改 `part.icon`；取消预览不改变图标文件与字段（相机状态可写回 `_uiState.iconCamera`，不进撤销）。视口在同一个同步任务内完成“隐藏 → 渲染 → 恢复”，不会闪烁。

### 5.4 输出路径与 `part.icon` 的三态

| `part.icon` 现状 | 文件动作 | 字段动作 |
|---|---|---|
| 指向本包 `textures/icon/` | 按“覆盖”写 / 跳过 | **不变**（沿用原路径） |
| 空 | 生成默认路径；若目标文件已存在且不覆盖，则**只关联该已有文件、不写文件** | 设为该路径 |
| 外部 namespace / 非 `textures/icon/` | 生成默认路径；按“覆盖”写 / 跳过 | 默认**不改写**；勾选“改写外部/依赖图标引用”才改写 |
| 目标文件因不覆盖被跳过，且字段已是本包路径 | 跳过 | **不变** |
| 外部字段 + 勾选改写 + 目标文件已存在 + 不覆盖 | 只关联已有文件，不写 | **改为本包目标路径**（linked） |

默认路径：

- 零件：`{namespace}:textures/icon/{folder}/{partId}.png`
  - `folder` 默认取 `partId.split('_')[0]`（`2s38_hull` → `2s38/`），与当前包一致；可在对话框覆盖。
- 装配体：`{namespace}:textures/icon/{folder}/{name}.png`
  - `name = Project.geometry_name || Project.name || 'assembly'`，必须 sanitize 成小写资源路径段。
  - `folder = name.split('_')[0]`（不是 `partId`）；也可沿用零件图标所在目录（若所有零件一致）。
  - 若与任一零件目标路径相同（例如 `mtlb` 零件 + `mtlb` 装配体都落到 `mtlb/mtlb.png`），自动改用 `{name}_assembly.png`；若 `assemblies/{name}.json` 已存在，预览必须额外提示：**P1 只用 `fs.existsSync` 检查存在性、不读取/不写该 JSON，若它的 `icon` 指向原冲突路径，需手工改为 `{name}_assembly.png`**，不能静默认为已生效。
- 若已有 `assemblies/{name}.json` 且其 `icon` 指向 `textures/icon/`，P2 优先沿用该路径；P1 不读取 JSON，直接用上述默认。

**不要**强制加 `_icon` 后缀；官方包与当前包命名不统一，沿用现有路径最安全。**文件被跳过时，已有字段保持不变；唯一例外是外部字段勾选“改写”且目标文件已存在：此时只关联并改写字段，不写文件。字段为空且目标文件本来已存在时，只做“关联”不写文件；字段为空且目标文件不存在时，写出文件并把字段设为该路径。只有写盘失败或 zip 内容包等无法写盘的情况，才保持为空。** 外部/依赖图标默认“不改写字段，只按覆盖策略处理文件”时，预览汇总必须明确标出“文件已生成/跳过，字段未改写”，避免用户以为没生效。

### 5.5 导出入口（P2）

在 [export_dialog.js](../src/ui/export/export_dialog.js#L336) 的表单中加：

```js
generateIcons: {
    type: 'checkbox',
    label: '导出前生成图标',
    value: false,
    description: '按上次的图标设置生成零件/装配体图标；会写入内容包 textures/icon 并更新 part.icon'
}
```

`onConfirm` 顺序：

1. `canExport` 闸门。
2. 若勾选，调用 `icon_generator.generate(...)`（异步/进度）。
3. `ops.updatePackMeta`。
4. `executeExport`。
5. toast 汇总（零件/图标/失败项）。

注意：当前 `onConfirm` 是同步的；生成 6～20 张图标需要改成异步或先弹独立进度对话框。**P1 不把生成塞进导出**，避免复杂化。导出勾选属于显式 opt-in：复用上次设置，不再逐张预览；若有失败/跳过，先在导出对话框汇总并让用户决定是否继续。

## 6. 技术设计

```
src/services/export_pipeline.js     # P2：换导出目录时复制 textures/icon
```

拆分纯函数的目的：`icon_paths` / `icon_visibility` / `icon_fit` 不依赖 Blockbench 全局，`bun test` 可以直接测；`icon_generator` 只做适配和副作用。`icon_visibility` 的输入用 plain node（`{uuid, name, parentUuid, children}`），由 generator 把 `Group.all` / `Cube.all` 映射进去；`icon_fit` 输入 AABB + 相机 right/up 轴；`icon_paths` 只接收字符串和布尔入参（包括 `targetExists`），**不读文件系统**。文件是否存在、内容包是不是 zip、`fs.existsSync` / `writeFileSync` 都由 `icon_generator` 负责；`icon_paths` 只根据传入的 `{ icon, kind, partId, namespace, folder, targetExists, overwrite, rewriteExternalIcon }` 返回计划。`icon_generator.js` 可以 `require('fs')` / `path` / Blockbench 全局，和 `export_pipeline.js` 的定位一致：**文件系统/渲染副作用，不进撤销，不暴露 MCP，不写 `_uiState`**。

### 6.2 零件 → 可见组（与 Java 侧对齐）

Java 的 `SubPartAttr.filterBones()` 语义是：

- 结束骨骼**自身**也被排除，不只是它的子树；
- 使用 `getEffectiveEndBones()` = `end_bones ∪ auto_end_bones`；
- `start_bone` 为空表示**整棵模型**，不是“回退当前显隐”。

因此：

```
可见集(sub_part) = start_bone 子树
                 − (每个 end_bone 自身 ∪ 其子树)
                 // end = end_bones ∪ auto_end_bones
start_bone 为空 → 整棵模型 − (每个 end_bone 自身 ∪ 其子树)
零件可见集 = 所有 sub_part 可见集的并集 + 各自祖先
```

对每个 `partId`：

1. 解析变体：`part.variants[activeVariantName]` 存在则用；否则取 `Object.keys(part.variants)[0]`；在结果中记录实际使用的变体。**不要**把当前工程的 `activeVariantName` 直接套到所有零件（2S38 当前是 `"2s38"`，但 skirt 只有 `left/right`）。若 `variant.model` 非空且归一化后与 `Project.geometry_name` / `Project.name` 不匹配，默认记录 warning 并继续（避免 `geometry_name` 为空、`Project.name` 是 `2S38_Vehicles` 这类命名漂移导致整批 0 图标）；只有 `strictModelMatch:true` 才跳过该零件。
2. 遍历该变体的 `sub_parts[*]`：
   - `start_bone` 为空 → 从整棵模型开始；否则从 `Group.all` 找 `start_bone`，找不到记录错误并跳过该零件。
   - `Group.all` 中存在多个同名 `start_bone` 时，默认取第一个并记录 `duplicate_start_bone` warning；`strictStartBone:true` 时跳过该 sub_part/零件，避免生成与 Java 侧不一致的图。
   - `end = end_bones ∪ auto_end_bones`；`auto_end_bones` 是运行时重算字段，不导出，但必须参与图标显隐。
   - 可见集 = start 子树 − 每个 end 自身及子树；`start_bone` 本身无条件保留（除非它恰好也在 end 列表中，按 Java 语义会被排除）。
3. 所有 sub_part 的可见集取并集。
4. 对每个保留组补祖先；其余 Group/Cube 隐藏。
5. 兜底：若该变体没有任何 `sub_parts` / 所有 start 都为空，则按“整棵模型”处理，并在结果中标记 `fallback: whole_model`，不要静默回退当前显隐。

> `auto_end_bones` 在本工程真实存在：2S38 hull 的 main 子零件 `end_bones` 为空，但 `auto_end_bones` 有 16 个轮子。对“零件级图标取并集”结果不变，但规则必须写对；遇到“end 不是任何 sub_part 的 start”或“单零件空 start_bone”的工程，漏掉它会漏几何/空白。

### 6.3 隐藏碰撞箱/交互区/连接点

- 遍历 `element_markers`，把 `hit_box` / `interact_box` 标记对应的 Group 子树隐藏。
- `connector` 标记是 Locator，无几何；`Canvas.withoutGizmos` 会隐藏 Locator sprite。
- 名称正则 `/hitbox|hit[_ ]?box|collision/i` 作为兜底。
- 上述被隐藏的辅助元素**不参与** §6.4 的“未声明组”统计；否则 2S38 的 `Skirt_Left_1_HitBox` / `Skirt_Right_1_HitBox` 会被误报。
- **不要按 `export === false` 过滤**：当前 2S38 的履带组就是 `export=false` 但可见，过滤会丢履带。
- **不要**隐藏所有 `export=false` 的骨骼/方块，除非用户显式勾选“隐藏不导出元素”（P3 可选）。

### 6.4 包围盒与坐标系

- Cube：`cube.getGlobalVertexPositions()`，走 `mesh.matrixWorld`，包含当前姿态、inflate/stretch。
- Mesh：`geometry.boundingBox`（为空则 `computeBoundingBox()`）× `mesh.matrixWorld`。
- 只统计“自身可见且祖先链全部可见”的元素。
- `getGlobalVertexPositions()` 内部会 `vec.sub(scene.position)`（[cube.js](../../blockbench/js/outliner/types/cube.js#L630)）；AABB 与相机 target 必须使用**同一 scene-local 坐标系**。Bedrock `centered_grid=true` 时 `scene.position = 0`，本工程无影响；其他格式需先确认/补偿。
- **整机 AABB 定义**：所有零件、所有变体的 `start_bone` 子树并集（减 end/auto_end）再并祖先；不含“未被任何零件声明”的组。
- **未声明组 warning 先过滤辅助元素**：只统计按 §6.3 隐藏碰撞/交互/Locator 之后**仍可见的几何**。`element_markers` 里的 `hit_box` / `interact_box`、名称命中 `/hitbox|hit[_ ]?box|collision/i` 的组、Locator 等非几何元素都不算“未声明组”。2S38 的 `Skirt_Left_1_HitBox`、`Skirt_Right_1_HitBox` 正属于这一类，**不应触发 warning**。过滤后仍有 Cube/Group 不在任何零件的可见集（含祖先）内，才 warning 列出。
- 整机图包含所有变体的几何（2S38 的左/右裙板都会显示）；若某零件的变体是互斥外观，P1 会重叠，需用手动显隐或后续按变体过滤。
- 如果为空：跳过并报“没有可见几何”。

### 6.5 相机与取景

默认：**正交 + 可复现方向 + 统一比例**。

1. 方向：`camera` 取 `project` / `iso` / `current`。`project` 用 `_uiState.iconCamera.direction`（缺失时回退 `iso`）；`iso` 用 `DefaultCameraPresets` 的等轴测；`current` 完整复制当前视口相机（position/target/zoom/projection），**只允许 `scope:'current'`**，此时忽略 `framing`。整批/装配体不允许 `current`，Dialog 直接禁用并提示。**首次默认 `iso`**，不默认当前视口，避免每次生成结果不同。
2. 取景：`framing` 取 `uniform` / `fit`，**不再有 `current`**。`uniform` 先隐藏 hitbox，量整机 AABB；由 AABB 在相机 right / up 方向的跨度求一次 `zoom`，每个零件只把 target 移到该零件 AABB 中心。`fit` 才对每个零件重新求 zoom。fill 可配置（2S38 用 0.86，k17 / sdkfz234 用 0.95，默认 0.9）。
3. 装配体：target 用整机中心，`zoom` 用整机比例（`uniform`）或整机 AABB 重算（`fit`）。
4. 成功后 service 只返回 `cameraUsed`（方向 / fill / framing）；由 dialog 写回 `_uiState.iconCamera` 并 `scheduleSave()`（`_uiState` 不进撤销）。**`icon_generator` 不写 `_uiState`**，保持服务层不落盘配置。

正交下是闭式解（`resize` 后 `camOrtho.right = width/80`）：

```
zoom = fill * min(
    width  / (40 * max(spanRight, 1e-6)),
    height / (40 * max(spanUp,    1e-6))
)
```

`spanRight` / `spanUp` 用 AABB 8 个角在相机 right / up 轴上点乘得到；比 NDC 迭代更短，也避免迭代把中心带偏。

> 只有 `camera:'current'` 才复制当前相机的位置/target/zoom/projection 到离屏相机，不再重算取景；它只允许“当前零件”，因为整批 7 张图都复制同一个整机视角会让零件图失去意义。注意视口不是正方形时，128×128 会裁掉左右或上下。首次想复刻现有 2S38 图标时，建议先对单个零件用“使用当前视角”对齐一次，成功后把方向写入 `_uiState.iconCamera`，后续批量走 `project`/`iso` + `uniform` 即可。

### 6.6 渲染

**关键顺序**：`setProjectionMode(true)` 必须在 `resize(512, 512)` **之前**。`setProjectionMode()` 内部会调用无参 `this.resize()`；离屏时 `canvas.isConnected === false` 且没有宽高，`resize()` 直接 return，`camOrtho` 会保持构造值 `(-600, 600, -400, 400)`（上下颠倒 + 3:2），512×512 画布就会翻转/拉伸。

```js
function acquirePreview() {
    var old = (typeof Preview !== 'undefined' && Preview.all)
        ? Preview.all.find(function (p) { return p.id === 'mm_icon_render'; })
        : null;
    if (old) old.delete();                       // 热重载残留

    var p = new Preview({ id: 'mm_icon_render', offscreen: true, antialias: true });
    p.setProjectionMode(true);                   // 必须先切正交
    p.resize(512, 512);                          // 再定尺寸：camOrtho 的 l/r/t/b 在这里才写入
    p.controls.minDistance = 1;
    p.controls.maxDistance = 100000;             // 避免 OrbitControls 夹取 distance
    p.controls.enableDamping = false;
    return p;                                    // 模块级复用，onunload 时 delete()
}

function computeZoom(width, height, spanRight, spanUp, fill) {
    return fill * Math.min(
        width  / (40 * Math.max(spanRight, 1e-6)),
        height / (40 * Math.max(spanUp,    1e-6))
    );
}

function renderIcon(p, center, dir, zoom) {
    var distance = 1200;                         // 显式给值，且 < controls.maxDistance
    p.camOrtho.position.copy(center).addScaledVector(dir, distance);
    p.controls.target.copy(center);
    p.camOrtho.zoom = zoom;
    p.camOrtho.updateProjectionMatrix();

    var bg = Canvas.scene.background;
    var fog = Canvas.scene.fog;
    Canvas.scene.background = null;
    Canvas.scene.fog = null;

    try {
        // 注意：withoutGizmos 内部 try/catch 吞异常（canvas.js:540），
        // 不能靠它做错误边界；渲染失败时要自己检测空图。
        Canvas.withoutGizmos(function () { p.render(); });
        return p.canvas.toDataURL('image/png'); // preserveDrawingBuffer=true（preview.js:298）
    } finally {
        Canvas.scene.background = bg;
        Canvas.scene.fog = fog;
    }
}
```

- 渲染 512×512，再用高质量 `drawImage` 缩到 128，作为 4× SSAA。
- 保留一个模块级 offscreen `Preview` 复用；[plugin.js](../src/plugin.js#L109) 的 `onunload` 必须调用 `icon_generator.dispose()`，否则热重载会持续泄漏 WebGL context（浏览器上限约 16 个）。
- `try/finally` 恢复 `Canvas.scene.background`、`fog`、Group/Cube 可见性；捕获异常，避免把视口留在“只剩一个零件”的状态。
- 检查 `CanvasFrame.isEmpty()` 或 alpha，空图跳过并报错。
- 主视口不闪：P1 **同步跑完整批**（7 张秒级），中间不让出事件循环；不要直接 `setTimeout` 分批。大批量（P3）才考虑“隐藏 `Preview.selected.node` + 暂停 Timeline”后分批。

### 6.6.1 着色 / 场景固定

图标颜色/贴图取决于 `Project.view_mode`、`settings.shading`、`settings.brightness`、`settings.tone_mapping`、`Canvas.global_light_color`、`Canvas.global_light_side`，以及 `PreviewScene.active` 的 fog / cubemap / preview_models。P1 默认**固定图标着色与贴图视口**，避免同一包在不同机器上风格不同：

| 项 | 图标生成时 | 恢复 |
|---|---|---|
| `Project.view_mode` | `'textured'`（**仅当当前不是 `'textured'` 时才切**） | 原值 + `Canvas.updateViewMode()` |
| `settings.shading` | `true` | 原值 |
| `settings.brightness` | `50` | 原值 |
| `settings.tone_mapping` | `'none'` | 原值 |
| `Canvas.global_light_color` | `#ffffff` | 原 Color |
| `Canvas.global_light_side` | `0` | 原值 |
| `Canvas.scene.background` | `null` | 原值 |
| `Canvas.scene.fog` | `null` | 原值 |
| `PreviewModel.getActiveModels()` | 若非空，临时 disable | 恢复 |

- 若当前是 `solid` / `colored_solid` / `wireframe`，仅调用 `Canvas.updateShading()` 不会恢复贴图，必须 `Project.view_mode = 'textured'; Canvas.updateViewMode()`。`updateViewMode()` 内部会 `updateAllFaces()` + `updateShading()`，只在确实需要切换时调用，避免每次生成都全量重建。
- 设置后调用 `Canvas.updateShading()` / `p.updateToneMapping()`，再渲染。
- `try/finally` 恢复，并再次 `Canvas.updateShading()`；若切换过 `view_mode`，恢复原值后调用 `Canvas.updateViewMode()`。`settings.tone_mapping` 恢复后对 `Preview.all` 逐个调 `updateToneMapping()`。不要在异常路径留下全局着色或非贴图视口。
- 如果后续提供“使用当前着色设置”选项，必须在 UI 中明确“跨机器可能不一致”，且不设为 P1 默认。
- 预览场景的 cubemap/fog 已处理；`preview_models`（展示台等）必须临时 disable，否则会进图标。

### 6.7 写 PNG 与更新 part.icon

- `fileWriter.ensureDir(dir)` + `fs.writeFileSync(filePath, Buffer.from(base64, 'base64'))`。
- 需要给 [file_writer.js](../src/utils/file_writer.js) 增加 `writeBinaryFile(dir, filename, buffer)`，或由 `icon_generator` 直接 `fs`。
- **逐零件**用 [doc/keys.js](../src/doc/keys.js#L106) 的 `isSafePartId(partId)` 判断（它同时检查 `partId.split('_')[0]`）；不安全就跳过并汇总。**不要**在图标批量里调用 [safe_part_ids.js](../src/services/safe_part_ids.js#L19) 的 `assertSafePartIds`——那是整包导出闸门，一个坏零件会让整批失败。
- **先解析 resource location，再做磁盘 containment，不能混用**：
  - `target` 必须匹配 `^([a-z0-9_.-]+):(.+)$`；`ns = config.namespace || 'machine_max'`。
  - 只有 `m[1] === ns` 且 `m[2].indexOf('textures/icon/') === 0` 才视为“本包可写路径”。`othermod:textures/icon/x.png` 是外部引用，不能因为字符串里含 `textures/icon/` 就被当成可写目标。
  - `resPath` 拒绝反斜杠、`..`、绝对路径/盘符；`file = path.resolve(contentPackPath, ns, resPath)`，`root = path.resolve(contentPackPath, ns, 'textures/icon')`，要求 `file !== root` 且 `file.startsWith(root + path.sep)`。只允许写到 icon 目录之内，不能写到 icon 目录之外。
  - 外部 namespace 的字段值只作为“外部引用”保留或按选项改写；写盘目标始终落在本包默认路径，不使用外部路径。
- 按 §5.4 状态表决定是否改写字段：文件被跳过且字段已是本包路径 → 不改；外部字段勾选改写且目标文件已存在 → 只关联并改写字段；外部/依赖图标默认不改写字段，文件按覆盖策略写/跳。
- PNG 写盘是外部副作用，不进撤销栈；`part.icon` 的修改走新的 `ops.setPartIcons`：

```js
function setPartIcons(config, options) {
```

批量一次 `runConfigEdit`，Ctrl+Z 一次回退所有路径；`mm_config_changed` 触发 `scheduleSave()`，不额外 `saveConfig()`。**如果 6 个零件的 icon 已经是目标路径，`icons` 为空，`setPartIcons` 必须返回 `changed:false` 且不新增撤销记录。**

### 6.8 装配体图标

- P1：只生成 PNG，默认 `{folder}/{name}.png`；不读取/不写 `assemblies/*.json`。
- `name = Project.geometry_name || Project.name || 'assembly'`（与 [export_pipeline.js](../src/services/export_pipeline.js#L196) 的兜底一致），再做资源路径 sanitize：转小写、非法字符替换、拒绝首尾点/Windows 设备名。
- `folder` 默认 `name.split('_')[0]`（`sdkfz234_2` → `sdkfz234`）；若所有零件图标已在同一目录，优先沿用该目录。
- **碰撞**：`mtlb` 这种无下划线的零件，零件默认 `mtlb/mtlb.png`，装配体默认也是 `mtlb/mtlb.png`。检测到与任一零件目标路径相同后，装配体改用 `{name}_assembly.png` 并在预览中提示；不要依赖“默认不覆盖”静默跳过。**若 `assemblies/{name}.json` 已存在（P1 只查存在性，不读内容），额外提示它可能仍指向旧冲突路径，需要手工改；P2 读取 JSON 后以 JSON 的 `icon` 为准，若仍与零件冲突则报错让用户处理，不自动改名覆盖引用。**
- 已有 `assemblies/{name}.json` 且 `icon` 指向默认路径时，生成同名 PNG 立即生效，无需改 JSON；没有 assembly JSON 时，PNG 只是给后续手工接线用。
- P2：若已有 `assemblies/{name}.json` 且 `icon` 指向 `textures/icon/`，优先沿用该路径。
- 若要自动写 `assemblies/*.json`，需要新增 assembly 数据模型/读取器；当前 `content_pack.js` 不处理 assemblies。建议 P2/P3 单独评审。

### 6.10 服务契约（建议）

```js
// services/icon_generator.js
generate(config, {
  scope: 'current' | 'all' | 'assembly' | 'all+assembly',
  partId: string?,
  variantName: string?,        // 仅当前零件；其余按 part.variants 解析
  visibility: 'auto' | 'manual',
  camera: 'project' | 'iso' | 'current', // current 仅 scope==='current'；project 用 _uiState.iconCamera
  framing: 'uniform' | 'fit',  // 无 'current'；current 由 camera 表达
  fill: number,                // 0.5–1.0，默认 0.9；camera==='current' 时忽略
  folder?: string,             // 仅新路径；缺省按 partId/name 前缀
  resolution: 128,             // P1 固定 128；256/512 留作后续扩展
  overwrite: boolean,
  rewriteExternalIcon: boolean, // 默认 false
  strictModelMatch?: boolean,   // 默认 false：不匹配 warning + 继续
  strictStartBone?: boolean,    // 默认 false：重名取第一个 + warning
  write: boolean,
  hideMarkers: boolean
}) -> {
  items: [{
    kind: 'part'|'assembly',
    partId?, variantName?, path,
    status: 'created'|'linked'|'overwritten'|'skipped'|'unrewritten'|'failed',
    fileAction: 'written'|'skipped'|'none',
    usedVariant?, fieldChanged?: boolean, error?
  }],
  summary: { created: number, linked: number, overwritten: number, skipped: number, unrewritten: number, failed: number },
  cameraUsed: { direction: string, fill: number, framing: string },
  errors: [{ partId?, message }]
}
```

状态分类固定为：`created` = 字段原为空且已设/已写；`linked` = 字段原为空、或外部字段勾选改写，但只关联已有文件、不写文件；`overwritten` = 字段已有且文件被重写；`skipped` = 文件被跳过且字段不变；`unrewritten` = 文件生成但外部/依赖字段未改写；`failed` = 失败。**同一个条目只计一类**。

返回结果由 dialog 负责 toast/展示、写回 `_uiState.iconCamera`；service 不 toast、不落盘配置、不写 `_uiState`、不刷新 Outliner。

### 6.11 性能与主视口

- 当前 3050 cubes × 7 张图：预计秒级。
- **P1 同步跑完整批**：隐藏 → 渲染 → 恢复都在同一个同步任务内，浏览器不会插入中间帧，主视口不会闪；代价是生成期间 UI 阻塞几秒，可接受。若要提示，可用阻塞式 `Dialog({ progress_bar })` 或状态栏文字，但不要在循环里 `await` / `yield`。
- **不要**直接 `setTimeout` 分批：一旦让出事件循环，主视口会画出“只剩一个零件”的中间状态，动画循环还会改变姿态。
- P3 若要支持 20+ 张：生成前 `Preview.selected.node.style.visibility = 'hidden'` + `Timeline.pause()`，结束后恢复；或使用阻塞式进度 Dialog。不要在没有隐藏主视口的情况下异步分批。
- 不要每次 `Canvas.updateAll()` 重建全部方块；直接切 `mesh.visible` + 必要时 `Canvas.updateVisibility()`。

| PNG 写盘不可撤销 | 撤销路径后文件残留 | 文档写明；可选备份 `.bak` |
| 性能 | 大批量卡 UI | P1 同步 7 张；20+ 走 P3 隐藏主视口方案；复用 offscreen Preview |
| 热重载 | 旧 offscreen Preview/隐藏状态残留 | `plugin.js onunload` 调 `dispose()`；注册前清理同 id |

补充默认（不单独提问，已写入正文）：

- 自动显隐：默认“按 start_bone 自动”，同时提供“使用当前显隐”。
- 覆盖：默认不覆盖已有文件；用户显式勾选才覆盖。
- 命名：优先沿用已有 `part.icon`；新建用 `{partId}.png`，不强制 `_icon`；外部/依赖图标默认不改写。
- 相机：默认 `camera:'project'`；`_uiState.iconCamera` 无记录时回退 `iso`。成功后由 dialog 写 `_uiState.iconCamera`；不默认当前视口。`camera:'current'` 只允许“当前零件”，此时完整复制当前相机，`framing` 不参与。
- 取景：`framing:'uniform'`（整机定一次 zoom）或 `'fit'`（每件重算）；不再有 `framing:'current'`。
- 变体：默认自动（active 存在则用，否则第一个）；仅“当前零件”可在对话框指定。
- 图标子目录：默认自动（`partId`/`name` 前缀），对话框可覆盖；只影响新建路径，已有 `part.icon` 原样保留。
- 严格匹配：`strictModelMatch` / `strictStartBone` 默认 `false`，即 warning + 继续；需要严格时再开。
- 填充率：默认 0.9；2S38 用 0.86，k17 / sdkfz234 用 0.95。
- 装配体文件名：`name = Project.geometry_name || Project.name || 'assembly'`；文件夹：`name.split('_')[0]`，不是 `partId.split('_')[0]`。

### 11.1 仍待实施时确认的细节

以下不阻塞 P1，但实现时需要在代码评审中定：

1. **预览对话框的呈现**：P1 定为“一次预览全部，确认后全部写入”，不做逐项勾选；若后续需要逐项选择，再升级。
2. **失败策略**：批量中某个零件找不到 `start_bone` 时，跳过并汇总（不中止全部）；结果中给出原因。
3. **“覆盖”粒度**：P1 用全局“覆盖已有文件”开关，不做逐项覆盖。
4. **图标子目录字段**：§5.2 已有该字段；默认自动，只在新建路径时生效，写入前按 resource path 段校验，非法值拒绝。
5. **装配体图标命名**：P1 用 `name`；若已有 `assemblies/*.json` 且 icon 路径冲突，P1 提示手工处理，P2 读取 JSON 后以 JSON 为准。
